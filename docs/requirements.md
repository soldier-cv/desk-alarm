# 需求与设计决策

代码里不写这些，写在这里。改行为前先看这里。

## 产品定位

到点强提醒的桌面工具。客户端与服务端分离，同一条提醒可指定推送到多台设备。

目标场景：一个人有多台设备（两台 Windows、一台 Android），在任意一台记一条，到点由服务端裁决推给该到的设备。

**不做**：文件内容管理。只存路径字符串，不读文件、不解析文件。

**不做**：Web 客户端。服务端有 HTTP API 和 MCP，但没有浏览器界面。

## 提醒强度：整个设计里最重要的一条

**提醒疲劳是提醒类工具死掉的头号原因。全都在喊，结果是全都听不见。**

| | 强提示 | 弱提示 |
|---|---|---|
| 表现 | 全屏接管窗口，关不掉，会重复响 | 只出通知和顶部细横幅 |
| 动作 | 完成 / 打开链接 / 推迟 / 静音 | 完成 / 推迟 10 分钟 / 忽略（写理由） |
| 升级 | 30 秒不处理就升级，5 分钟后每 2 分钟重复 | 永不升级 |
| 默认 | 给了时间就是强提示 | 进收集箱的、agent 建的，默认弱 |

### strength 和 bypassQuiet 是两个正交字段

必须拆开：「服药」要 strong 且绕过静音，「站起来走走」要 weak 且不绕过。两个字段塞一起就表达不了这四种组合。

### 忽略和完成必须分开记

- `done` = 我做完了
- `dismissed` = 我看到了，故意不处理

分开的全部意义在于下面这个判断：

> 一条被忽略 2 次的条目自动降级为弱提示；被忽略 3 次提示「建议删除」。

这是 App 在告诉你一件关于你自己行为、而你本来看不见的事。

## 强提示的升级阶梯

实现在 `app/src/alarm.ts`，只有这一份，主窗口持有它，takeover 窗口只负责画。

| 时点 | 行为 |
|---|---|
| 0 秒 | 系统通知 + 接管窗口亮起 |
| 30 秒 | 还没处理就加抖动，用户试图关窗也关不掉 |
| 5 分钟 | 进入重复提醒，之后每 `repeatEverySec` 再响一次 |

**停止条件只有两个**：用户处理了，或者别的设备已经处理了。

weak 强度不走这条路径，只出一条通知和主窗口顶部的细横幅。分流在 `shouldRing()` 里做。

## 临近梯度

列表里唯一的颜色梯度。安静是常态，只有快到了才逐级变暖。

| 档位 | 条件 | 表现 |
|---|---|---|
| 无 | > 24 小时 / 收集箱 / 已完成 | 无色 |
| soon | ≤ 24 小时 | 行首渗入 5% 强调色，暖灰点 |
| close | ≤ 1 小时 | 9%，暖棕点，时间变「还有 X 分钟」 |
| due | ≤ 15 分钟 | 14%，强调色点开始呼吸（2.6 秒一次，只动透明度） |
| over | 已逾期未处理 | 19%，强调色点，钟点后标「· X 还没处理」 |

**用四级而不是连续渐变**：连续变化在列表里会变成噪声，离散步进才一眼可读。

梯度只从行首向左渗入（`linear-gradient(90deg, …)`），和 hover/选中用的背景色是两层，互不覆盖（`background-image` 和 `background-color` 分开声明，用 `background` 简写会把渐变清掉）。

临近度随时间自己往前走，事件驱动的刷新不会推进它，所以客户端每 20 秒原地更新行，不改列表整体 innerHTML，滚动位置和选中态不丢。

**一小时内不报钟点，报「还有 X 分钟」**：临近期限时，差多少比几点钟有用得多。

## 服务端是唯一的计时权威

`fired_at` 只由调度器写。客户端不判断「到没到点」，只接收服务端推送。

原因：客户端时钟不可信，多设备之间也不同步。如果允许客户端自己判断触发时间，同一条提醒在不同设备上可能差几分钟，甚至在时钟漂移的机器上永远不触发。

倒计时和「还有 X 分钟」这类显示，用 `serverNow()`（客户端与服务端的时钟偏差），不用本地时间。

## 事务性发件箱

调度器只写 `deliveries` 行（状态 `pending`），由独立的轮转器负责真正发送。两个循环独立。

`delivered` 的含义是「传输层确认收到了」，不是「我发出去了」。这个区分很重要，否则无法判断该不该重试。

**踩过的坑**：`markDelivered` 曾经被 import 了但一次都没调用，`deliveries.state` 永远停在 `pending`，而推送只发给活着的 WebSocket。结果是手机锁屏就静默丢提醒，还会误报成 missed。改成分工明确后不再出现。

## 忽略次数驱动降级

2 次自动降级 strong → weak，3 次提示删除。降级是系统对用户行为的学习，不是惩罚。

## MCP 的防呆规则

三条，写操作的约束：

1. 写操作先 `plan_changes` 干跑，再 `apply_changes` 执行
2. 建强提示必须给 `reason`
3. `idempotencyKey` 防重

`plan_changes` 返回的 `plan_id` 一次性、10 分钟过期。

**为什么 agent 建强提示要强制 reason**：界面上的强提示是用户自己按下的，用户已经想清楚了；agent 建的强提示是机器推断的，可能误判。没有理由的强提示会被接管窗口反复轰炸用户，这是最坏的结果。所以要求 agent 说明理由，把判断责任显式化。

**为什么写操作要分两步**：MCP 是给了模型一把锤子，危险的是 create（会把你从专注里炸出来）和批量改期（一次挪二十条）。解法不是把工具藏起来，而是要求 `plan_changes` 先干跑、`apply_changes` 再执行，让破坏性操作的意图必须明确。

一句话概括：一个能随便建全屏强提示的 agent，早晚会半夜三点为一份草稿邮件把你叫醒。

**为什么 HTTP 建条目不强制 reason，只有 MCP 强制**：客户端界面已经问过用户了，再问一遍是多余的。agent 没有界面，必须强制。

## 服务端地址可配置

服务端部署在 CI（Woodpecker 推 tag 自动发布），客户端装到不同机器上要能自己指到服务端，不能硬编码。

**两个入口**：

- 登录页最上面的「服务端地址」输入框，带「测试连接」按钮
- 登录后点顶栏的连接状态，打开切换面板

**地址必须能测通**。用户填错地址是最常撞的坑，只给一句"连不上"会让人以为是口令错。测试按钮打 `/healthz`，区分「地址格式不对」「连不上」「超时」「那个地址上没有 DeskAlarm 服务」，顺便回填时钟偏差。

**填 `host:port` 不用带协议**，自动补 `http://`。但已带 scheme 的必须原样解析：早期版本对 `ftp://x.com` 补协议补成了 `http://ftp`，是 scheme 注入。

**换地址等于换机器**：旧 token 对新地址无效，所以切换时清掉会话重新登录，不要让用户以为地址没生效。

## 端口

- 网关 **8091**（`.env` 的 `WEB_PORT`）：静态原型 + API 反代
- API 直连 **8787**：客户端默认连这个
- `8090` 被本机一个 Python/FastAPI 服务占着，而且它会抢走 `127.0.0.1:8090` 的回环流量。这种故障特征是「服务看起来活着但响应格式不对」（返回 `{"detail":"Not Found"}`），比连不上更难查

## 数据库隔离

`general_db` 是共用库（还有 `image_gallery` / `image_gallery_dev` / `porter`），所以全部表隔离在 `desk_alarm` schema，通过 `search_path` 生效，`public` 保持零表。

不用 `pgcrypto`：`gen_random_uuid()` 从 PostgreSQL 13 起是内核函数，共用库里装扩展经常没权限。

## 暗色主题

深色界面里「深字配深底」是这个项目最容易翻车的地方。正文对比度 ≥ 4.5:1，UI 控件边界 ≥ 3:1。改色板必须跑 `node scripts/contrast.mjs`，不靠目测。

## 设计取舍

**视觉密度高**：桌面常驻工具，一屏要能看到所有待办。DENSITY 7。

**变化少**：颜色只有近黑基底 + 唯一强调色 `#FF5C2B`，强调色只用于到点、逾期、主行动。VARIANCE 4。

**动效克制**：只有「还有 15 分钟」的级别点会呼吸，2.6 秒一次，只动透明度不动大小和位置。MOTION 3。

**安静是常态**：超过 24 小时的条目没有任何颜色。不主动制造紧迫感。
