# 提醒模型：强弱二值 + 截止时间单一时钟

> 状态：当前实现目标。本文取代 `docs/drive-engine.md` 的 L1–L5 停滞阶梯；后者保留为历史设计记录。

## 为什么改

L1–L5 用「停滞多久」当主时钟，导致用户明明写了截止时间，到点却只发一条通知，还要再等几天停滞才升级到弹窗。等级阈值、强打扰额度、权重排序、L3 横幅队列、L5 自动归档彼此叠加，规则多而难预测。

新模型把时钟还给用户：**每条记录只有一个时间节点 `dueAt`**，由强弱二值决定到点后的表现形式。系统不再猜「该催到什么程度」。

## 规则（唯一真相）

### 强弱来源

记录只有**强提醒 / 弱提醒**两种类型，用户在捕获页和详情页直接选，没有「重要性」星标概念，措辞关键词也不参与判定。

| 类型 | 到点表现 | 未填截止时间的默认值 |
|---|---|---|
| 弱提醒 | 系统通知 | `now + 1 天` |
| 强提醒 | 接管弹窗 | `now + 2 小时` |

内部仍沿用数据库的 `importance` 列作为存储位（弱存 0、强存 3），API 契约用 `strength: 'strong' | 'weak'`；这一层不暴露给用户。

### 时间节点

- 写入记录时若解析不到用户给的时间，按上表默认值补 `dueAt`，并在编辑页展示、可改。
- 客户端输入解析支持中文时段：`下午5点`、`下午5:30`、`5点半`、`明天下午5点`、`晚上8点` 等；「上午/中午/下午/晚上/凌晨」按 12 小时制换算，过点顺延一天。
- 用户改 `dueAt` 就是新节点：nudge 的 fireKey 绑定 `dueAt`，因此会重新触发一次。
- 所有列表按 `dueAt` 升序排列，逾期在前；静音时段内到点的提醒延后到静音结束再发。
- 周期性事项到点后照旧推进下一次 `dueAt`。

### 表现与重复

- **强提醒**：到点弹接管窗，桌面置顶不可关闭，手机端为不可关闭全屏模态；同一时间窗内的多条合并成一个队列逐条处理。逾期未处理时由服务端按衰减间隔继续复催（`0 / 15 分钟 / 1 小时 / 之后每 2 小时`），静音时段跳过；任意设备上线时，`welcome.overdue` 携带所有逾期未处理的强提醒并直接拉起接管窗（即使之前曾送达给其它设备），避免关机、重启或离开电脑漏掉。
- **弱提醒**：到点发单条系统通知，逾期未处理时由服务端在 `+30 分钟` 补发一次单条通知；逾期超过 `3 小时` 后不再逐条打扰，改为每 `3 小时` 发送一条用户级汇总通知（`pursuit.overdue_digest`）。设备上线时若存在逾期弱提醒，合并为 1 条汇总通知，不连环轰炸。静音时段暂停，出静音后补发；任意设备跟进后广播停止。

### 跟进动作

| 动作 | 语义 |
|---|---|
| 完成 | 完成整条事项（标记 `done`）；单个步骤在步骤清单里单独勾选 |
| 延期 | 用户指定新 `dueAt`，新节点重新提醒 |
| 拆小 | 打开步骤编辑器带出该条全部已有步骤，可改文字、删行、加行后一次保存；带 id 的步骤保留完成态，未提交的旧步骤删除，并重设 `dueAt`（用户填的时间，否则按强弱默认值，取更早者）；提醒文案指向当前步骤 |
| 归档 | 显式结束 |

`partial`（推了一点）不再暴露为 UI 动作，历史里保留其旧记录并显示为「推了一点（未完成）」，据此对齐「只有完成，推了一点仍是未完成」。

### 逾期归档

`archiveAfterDays` 为服务端配置项（默认 30 天），按 `dueAt` 计算；超期自动 `status=archived`，并在跟进历史写 note「截止已过 N 天，自动归档」。强弱一视同仁。

## 数据表示

- `nudges.level` 列保留为整数，但只使用两个值：`2 = 弱提醒通知`、`4 = 强提醒弹窗`；不再有 1/3/5。
- `NudgeLevel` 类型收窄为 `2 | 4`；`FocusResult.budgetLeft` 删除。
- Settings 删除 `escalateAfterMs`、`dailyStrongBudget`，新增 `archiveAfterDays`。
- 移除已无实际作用的 `pursuits.nature`（一次性/项目）及 `MyStats.byNature`：`schema.pg.sql` 附带幂等 `ALTER TABLE pursuits DROP COLUMN IF EXISTS nature`，老库升级启动自动清理；服务端静默忽略旧客户端请求体可能附带的 `nature` 字段。

## 投递保证

设备离线时 nudge 留在 `pending`，调度器按重试间隔重试；重连后 `welcome.missed` 补发。没有任何在线设备时**不得**标记 delivered，否则该条永久丢失。

## 决策日志

| 决策 | 采用 | 否决的替代 | 理由 |
|---|---|---|---|
| 主时钟 | 用户设定的 `dueAt` | 停滞时长阶梯（L1–L5） | 截止时间才是用户定义的硬约束 |
| 强弱判定 | 用户直接选强/弱 | 星标、关键词推断 | 重要性星标是多余概念，措辞判语气不判代价 |
| 强提醒表现 | 到点直接弹窗，多条合并 | 逐级升级 + 每日额度限流 | 额度会压掉到点的重要事项 |
| 弱提醒 | 封顶通知，持续重复 | 只发一次 | 错过一次等于没提醒 |
| 拆小 | 全量替换步骤（增删改）+ 重设父项截止时间 | 拆成独立子项 / 步骤自带截止时间 | 不引入父子实体，避免弹窗被子项淹没 |
| 性质字段 | 移除 `nature`（一次性/项目） | 保留静态分类标签 | 重复由 `recurrence` 决定，拆步骤不限类型，该字段不参与任何调度决策 |
| 逾期归档 | 单一 `archiveAfterDays` 配置 | 按等级自动归档 | 保留清理能力但不恢复 Lx |
